# web-paper-to-pdf

Convert a Distill-style web paper (transformer-circuits.pub, distill.pub, alignment.anthropic.com) into a clean academic-style PDF using LaTeX with the public NeurIPS 2024 template.

Browser `print-to-pdf` on these papers tends to produce poor layouts: floating TOC sidebars overlap text, `<hr>` + `<h2>` page-breaks insert blank pages, and figures don't size correctly. This plugin instead walks the JS-rendered DOM, extracts math / citations / figures, and compiles a real LaTeX paper.

## Disclaimer

- This plugin produces **unofficial archival renderings**. PDFs generated by it carry a footnote on the first page stating that they are not produced or endorsed by the original authors.
- It is intended for personal reading / archival use only. Respect the copyright and license terms of the source page.
- Not affiliated with Anthropic, Google DeepMind, or any other organization mentioned in source papers.
- The `neurips_2024.sty` file is the **public** NeurIPS 2024 style template by Roman Garnett and contributors (the same file shipped with arXiv submissions); redistributed here for convenience.
- LaTeX output is best-effort. Interactive widgets (sliders, dropdown explainers, hover-popovers) cannot be preserved in a static PDF — if you need those, read the original web version.

## Scope

Tuned for:
- ✅ `transformer-circuits.pub`
- ✅ `distill.pub`
- ✅ `alignment.anthropic.com` (Distill-derived template)

Not tuned for:
- ❌ Generic blog posts (Substack, Medium, personal blogs) — use `chrome --print-to-pdf` instead
- ❌ arXiv HTML pages (`ar5iv`) — different tag set
- ❌ Documentation sites (MkDocs, Docusaurus, etc.) — overkill for non-paper content

## Requirements

- Python 3 with `beautifulsoup4`, `lxml`, `requests`
- `pdflatex` and `bibtex` (TeX Live, MacTeX, etc.)
- Google Chrome (headless mode used to dump the JS-rendered DOM)

On macOS the script assumes Chrome lives at `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`. Adjust `fetch_rendered_html()` in `convert.py` if you're on another platform.

## How it works

1. **DOM dump** — `chrome --headless --dump-dom <url>` waits ~15 s for JS widgets to render, captures the resulting HTML.
2. **Parse** — `beautifulsoup4` walks the tree, mapping Distill custom tags to LaTeX:
   - `<d-math>` → `\(...\)` (inline) or `\[...\]` (block)
   - `<d-cite key="foo,bar">` → `\cite{foo,bar}` (numeric square-bracket style)
   - `<d-footnote>` → `\footnote{...}`
   - `<figure>` / `.gdoc-image` → `figure` environment with caption
   - `<div class="authors">` / `<div class="affiliations">` → NeurIPS author block (rows of 4, `\quad`-separated)
   - `<h2/h3/h4>` → `\section* / \subsection* / \subsubsection*` (unnumbered)
   - Leading paragraphs before the first heading → `\begin{abstract}` block
3. **Download** — fetches `bibliography.bib` and all linked images to a working dir (cached by URL hash).
4. **Compile** — `pdflatex → bibtex → pdflatex → pdflatex`.

## Manual invocation

```bash
WORK=/tmp/paper-$(date +%s)
python3 ~/.claude/plugins/web-paper-to-pdf/skills/web-paper-to-pdf/convert.py \
  https://transformer-circuits.pub/2026/nla/ --out $WORK
cp ~/.claude/plugins/web-paper-to-pdf/skills/web-paper-to-pdf/neurips_2024.sty $WORK/
cd $WORK
pdflatex -interaction=nonstopmode paper.tex >/dev/null
bibtex paper >/dev/null
pdflatex -interaction=nonstopmode paper.tex >/dev/null
pdflatex -interaction=nonstopmode paper.tex
cp paper.pdf ~/Downloads/<name>.pdf
```

When invoked through Claude Code, the agent handles all of this — just say "save this paper as PDF" with a transformer-circuits / distill URL.

## Trigger phrases

- "save this paper as PDF"
- "把这个论文保存成 PDF"
- "用 latex 渲染"
- "PDF 效果不好" (when the previous attempt was a browser print)
- Any URL on `transformer-circuits.pub`, `distill.pub`, or `alignment.anthropic.com`

## Known limitations

- **SVG figures are skipped** — would need rasterisation.
- **Interactive widgets** (sliders, hover explainers) won't translate to PDF.
- **Math macros** beyond `\R \E \N \Z` defined in the preamble need to be added by hand to `convert.py` if a paper uses them.
- **Table rendering** uses fixed `p{3cm}` columns — non-trivial tables will look cramped; edit `render_table()` for custom widths.
- Output PDF cites the **current date** as the rendering date, so two builds on different days will differ in that field.
